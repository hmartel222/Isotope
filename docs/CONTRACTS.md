# Contract guide — Phase 1 contracts, Phase 2 execution

## Source of truth

`packages/core/src/contracts.ts` defines TypeBox schemas and TypeScript types inferred from those schemas. `packages/core/src/validation.ts` provides `validateContract(name, value)` and cross-artifact repair prerequisites. Validation never coerces or mutates input. JSON Schema snapshots in `packages/core/schemas/` are generated by `pnpm build`; edit TypeBox definitions, never snapshots. `changespec.schema.json` occupies the v3-required location.

`packages/core/src/stages.ts` defines the public stage inputs/outputs. Unimplemented stages export typed stubs that throw `NotImplementedStageError`. Phase 2 implements the narrow TS harness, differ, mechanical verdict resolver and explicit spec loader. Core has no subsystem dependencies. All other subsystem packages depend only on core. The CLI now orchestrates changespec, harness-ts, and differ for the explicit Phase 2 specimen; broader orchestration is deferred.

## Artifact chain

All paths are owned by `packages/core/src/artifact-paths.ts`:

```text
.isotope/
  selected-specs.json
  bdg.json
  signatures/<codeVersion>/<fixturePair>/<entryPoint>.<payloadVersion>.<run>.json
  diff-report.json
  diffs/<codeVersion>/<fixturePair>/<entryPoint>.<comparisonKind>.json
  evidence-packets/<entryPoint>.<divergence>.json
  reasoning/<entryPoint>.<divergence>.<vote>.json
  cache/<key>.json
  verdict.json
  repair/packets/<repairId>.json
  repair/candidates/<repairId>.json
  repair/proposals/<repairId>.json
  repair/verification/<repairId>.json
  repair/verified-repair.json
  isotope-report.json
```

Dynamic identifiers are encoded and traversal/separators are rejected. The code-version and fixture-pair directories prevent original/patched or planning/held-out runs overwriting each other. `comparison(...)` reserves distinct original/baseline/secondary comparison artifacts for multi-entry-point and repair runs. `diff-report.json` remains the canonical single-comparison location. The final report references all comparisons. Deterministic candidates may skip proposals per v3, but their full candidate is retained with any verified repair.

`writeJsonArtifact(root, path, contractName, value)` and `readJsonArtifact(root, path, contractName)` validate typed JSON. Pass `artifactPaths(projectRoot).root` as the artifact root. `ensureArtifactDirectories(projectRoot)` creates the hierarchy. Paths must be physical (no symlink components); use a canonical project path. Helpers reject lexical escape and symlink components. They are local runner helpers, not a defense against a concurrent adversary replacing directories during an operation.

JSON output is UTF-8, recursively key-sorted, two-space indented, and newline-terminated. Arrays retain order. Non-JSON input is rejected rather than silently dropped. This is artifact serialization only: the Phase 2 harness has its own bounded behavior serializer; Buffer/function/cycle support remains later work.

## Decisions and v3 ambiguities

- **Unspecified envelopes:** v3 gives partial examples, not full schemas for BDG, selection, reports, or verification. Phase 1 adds `schemaVersion: 1`, explicit IDs/references, and structured verification records. `VerdictReport` aggregates per-entry-point `VerdictResult` records. `IsotopeReport` retains candidate/verification references and audit hashes/raw-response references.
- **ChangeSpec drafts:** `ChangeSpec` permits `verified_by: draft` for the offline drafting output. `SelectedSpecs` requires human verification and a verification date. Repair prerequisite validation requires a distinct held-out pair when repair is enabled. No selector is implemented.
- **Config:** the schema models normalized, explicit settings; no YAML loader or implicit defaults are implemented. `repair.verify` is always literal `true`, including when mode is off, following v3 §4’s stronger rule. Limits are one primary attempt, at most three files, and at most 80 changed lines. A later mechanical retry is not an extra primary attempt.
- **Vocabulary:** serialized ChangeSpec fields retain the spec’s snake_case. Runtime artifacts use its camelCase. Canonical semantic tier is `semantic_question` from §3.5’s JSON example. Canonical configured adapter is `express_route` from §4; the prose’s `express` describes that adapter. Candidate origins are `deterministic` and `model`.
- **Non-candidate responses:** `human_decision_required` and `no_safe_repair` use `patch: null`. A repair candidate requires nonempty anchored edits. Replacement text can be empty to express a deletion; application, allow-lists, anchor uniqueness, and line-budget enforcement remain later work.
- **L6 placement:** pure verdict-resolution interfaces/stubs live in core as §2.5 specifies. Phase 2 implements only the pure mechanical verdict subset there; no orchestration or handler execution lives in core.
- **CLI exit status:** help/PASS return 0, FAIL returns 1, INDETERMINATE returns 4, malformed config/arguments return 10, and unimplemented commands retain scaffold-only code 12. Unsupported semantic residuals return INDETERMINATE in Phase 2; v3 ESCALATE routing comes with the complete verdict/reasoner stage.

## Verification boundaries

`RepairVerification` distinguishes planning and held-out evidence and all seven outcomes. Successful records require passing verdicts, baseline equivalence, stability, and all structural checks. Original baselines and patched signature references are explicitly recorded. Runtime relational validation additionally checks repair IDs, fixture IDs, distinct held-out pairs, and self-comparison run indices. `VerifiedRepair` can contain only an eligible candidate and a successful verification, and is always `offeredOnly: true`. Schema acceptance validates shape; Phase 9's L10 implementation supplies authority by independently rebuilding and re-executing the patched workspace.

The repair packet intentionally has no held-out field. Its builder must later enforce v3’s stronger exclusion of held-out payloads, signatures, and identifiers from every string/fragment; a shape schema alone cannot establish information provenance. Packet line/token budgets, policy predicates, verdict authority, and post-patch structural checks are interfaces/recorded constraints here, not implementations.

## Phase 1 audit

All v3 L0–L12 locations are reserved; package dependencies are acyclic. All seven verdicts, mechanical/reasoned/unavailable provenance, both proposal origins, planning/held-out pairs, original/patched code versions, and every repair outcome are representable. Candidate patches remain non-authoritative. JSON Schema snapshots and runtime tests cover all 27 registered contracts, with additional compile-time literal-union checks. At the end of Phase 1, no provider SDK or execution harness was present. Phase 2 adds Stripe types for the specimen and a mocked Vitest harness. AST, model, GitHub, patch application, and autonomous Git implementations remain absent.

## Phase 2 audit and limitations

No existing serialized schema or stage input/output shape was changed. Core gained an explicit, containment-checked `removeJsonArtifact` helper for clearing stale runtime output before a re-run. `Signature` keeps codeVersion, fixturePair, runIndex and durationMs. `behavioralView` in differ alone defines equality as returned/threw/calls. The same comparison can be reused by the future repair verifier.

The narrow harness uses Vitest’s programmatic API and pre-import mocks ([Vitest mocking API](https://v3.vitest.dev/api/vi)). Each invocation runs in a fresh child process and reloads the fixture. The runtime driver is an internal `.mjs` asset; only the actual specimen and package TypeScript are typechecked. Tests execute the runtime driver directly.

The differ supports identity, value-to-missing, dropped calls, new-only throws, and unstable self-comparisons. Other changes are retained as semantic questions; the Phase 2 resolver explicitly returns INDETERMINATE with `unsupported_semantic_difference_in_phase2`. This is a deliberate phase-boundary restriction, not the final v3 semantic routing rule. No model can be invoked. Arrays are positional and never sorted. Call alignment is deliberately conservative and not yet a general edit-distance algorithm.

Undefined is retained as the v3 `__undefined__` sentinel. Dates and ordinary JSON values are supported; unsupported behavior serialization invalidates the harness rather than turning two instrumentation failures into PASS. Sentinel collisions and exotic values need dedicated hardening later. Mock capture snapshots at the attempted side-effect boundary.

Spec selection and BDG construction remain visibly static. The supplied known spec validates, and its human marker is inherited from the user-provided specification. Fixture metadata is shape-checked but not a provider-provenance certificate. Tests use synthetic fixtures only under harness-ts/test-fixtures. Real-provider acceptance is blocked on the real pair; there has been no provider capture, normalization, code repair, Git operation, hosted service, or live database.

Phase 3 should begin at `packages/harness-ts/runtime/specimen.test.mjs`, whose fixed mock shapes and limited egress/determinism controls are the weakest generalization seam. No Phase 3 implementation has begun.
