# Dependency detector and ChangeSpec selector (Phase 6)

`selectChangeSpecs({ repositoryRoot, baseRef, headRef, specsRoot? })` is a local, deterministic L1 boundary. It reads Git objects with `git diff --name-status -M` and `git show ref:path`; it never checks out, fetches, mutates, invokes GitHub, or calls a model.

Supported changed dependency files are `package.json`, `package-lock.json`, `pnpm-lock.yaml`, `requirements.txt`, `pyproject.toml`, and `poetry.lock` at any monorepo depth. Manifest declarations cover npm dependency sections and exact Python pins. Lockfiles are preferred for resolved versions; package-lock v2/v3 `packages` and nested dependency forms, pnpm YAML snapshots/packages, and Poetry package blocks are supported. Unresolved ranges are reported diagnostically and never turned into guessed transitions. Lockfile packages are correlated with the workspace manifest, so incidental transitive churn does not select provider specs.

The normalized seam is `DependencyChange { ecosystem, package, fromVersion, toVersion, sourceFiles }`. Identical resolved transitions are deduplicated with sorted evidence paths. npm identity preserves scoped names; PyPI identity uses PEP 503-style lowercase hyphen normalization. Semver comparison recognizes prereleases and PEP 440 comparison handles numeric release components and common pre-release labels. Selection uses one threshold predicate: `from < breaking_from <= to`; downgrades and already-crossed thresholds do not match.

The registry is loaded from committed YAML, sorted by ID, and validated against the canonical ChangeSpec schema. Valid drafts are retained only for diagnostics and are never selectable; malformed specs raise a configuration error. Only `verified_by: human` specs with a verification date can enter `SelectedSpecs`. Multiple matching specs and package transitions are retained deterministically.

The explicit `isotope verify --base <ref> --head <ref>` path writes `selected-specs.json`, prints compact dependency/selection evidence, and stops with SKIP/exit 0 plus validated verdict/report artifacts when no spec matches. It does not invoke L2, L3 or L4. With a selected spec it passes that artifact into the existing real resolver → harness → differ → verdict pipeline. The old explicit walking-skeleton API remains available for L2 debugging; it still requires a human-verified known spec. `scan` remains an explicit L2 debugging command. GitHub, Dependabot, drafting, semantic reasoning, repair, Python execution and fleet remain out of scope.
